## 1. 영상 핵심 분석

### 비즈니스 모델
| 항목 | 내용 |
|---|---|
| 포맷 | **일본 시청자 대상 '팬튜브' 쇼츠** — 유명 연예인 영상 + 인기 OST + 빠른 칭찬 자막 |
| 성과(출연자 주장) | 영상 1개 1.6억 회, 그 영상 하나로 구독자 10.6만 명·약 1,550만 원. 채널 수익 약 2억 원, 전체 2.3~2.4억 원 |
| 수익원 | 쇼츠 광고 수익(YPP) / 확장: 라쿠텐 제휴 쇼핑 쇼츠 |
| 핵심 논리 | ① 이미 유명한 사람의 **트래픽**을 빌림 → 조회수 하한선 확보 ② 칭찬만 하므로 기획사 입장에서는 무료 바이럴 ③ 10초 내외 + 빠른 자막 → **시청 지속률 100% 이상(150~240%)**, 즉 반복 시청 |
| 운영 철학 | 편집은 프리랜서에게 맡기고 본인은 **기획(소재·트렌드 선별)**에 집중 |

### 워크플로우 (영상 속 수동 작업)
| # | 단계 | 영상 속 방법 | 타임코드 |
|---|---|---|---|
| 0 | 트렌드 감 키우기 | 좋아요/댓글 영역을 엄지로 가리고 끝까지 본 뒤 조회수 예측 → 확인 훈련. 내부 툴로 24시간 급상승 쇼츠·연령대별 관심사·추정 수익 확인 | 22:48, 24:35 |

| 2 | 기획안 생성 | Gem '인물 팬튜브 디렉터'에 이름 입력 → 프로필·대표작·연관 음악·자막 30개 | 6:08 |
| 3 | 소스 검색 | YouTube 설정 → 국가 **일본** (VPN 불필요) → 필터 **크리에이티브 커먼즈** | 7:41–8:53 |
| 4 | 다운로드 | 자체 다운로더(틱톡/인스타/유튜브 등 링크 입력) | 9:26 |
| 5 | 음악 | Gem이 추천한 연관곡(예: Lemon)의 후렴 부분만 잘라 오디오 추출 | 10:17–11:41 |
| 6 | 편집 | 캡컷 '장면 분할' → 얼굴 나온 컷만 남김 → **가장 예쁜 컷을 첫 장면** → 확대(얼빡) → 컷 나열 약 10초 | 11:42–14:39 |
| 7 | 제목 | 2줄, 인물명 포함, 일본어. 굵고 단정한 폰트, **쨍한 노란색** | 15:10–16:27 |
| 8 | 자막 | 배경 깔고 자막 1개당 **1.5~2초**, 조사 **の / は** 뒤에서 줄바꿈 | 16:36–18:48 |
| 9 | 효과음 | 컷/자막 바뀔 때마다 클릭음. 일본 밈 효과음 300여 개 시트 | 19:48–21:27 |

> **이 프로그램은 9번(효과음)을 구현하지 않습니다.** 사용자 결정으로 효과음 경로·설정·기본 자산을 모두 제거했습니다. 어떤 스타일에서도 효과음을 넣지 않으며, 예전 config의 `sfx_dir`/`cut_sfx`/`sfx_volume` 키는 무시됩니다.

### 이 프로그램에 반영한 값 → `config.yaml`, `shorts/styles.py`
- 기본 출력은 **무음** (원본 소리 제거, 효과음 없음). BGM은 `audio.music_path`를 직접 지정한 경우에만
- 목표 30초 / 최대 32초. 장면이 모자라면 반복·정지 화면으로 채우지 않고 **짧게 완성하고 이유를 표시**
- 화면 = [제목 | 영상 | 추가 자막] 세 영역. 추가 자막은 **영상 아래 전용 영역** (얼굴·원본 화면을 가리지 않음)
- 스타일 프리셋: **청춘·설렘(`youth_romance`, 신규 기본)** / 칭찬 나열형(`praise_list`, 기존 동작)
- 첫 컷은 자동 점수(얼굴 크기·안정성)로 정하지만, **웃는 장면 등은 사람이 썸네일·마커로 지정** (자동 표정 인식 없음)
- **원본에 자막·텔롭이 박힌 장면, 사진 슬라이드쇼·멈춘 화면은 자동 제외** (장면 30% 이상에서 글자가 보이면 영상 통째로). 간단한 영상 처리 휴리스틱(OCR 아님)이라 썸네일의 📝/🖼 표시로 확인
- 자막 84px·제목 96~100px, 4:5 배치는 제목 320 / 영상 1280 / 자막 320px

## 2. 자동화 아키텍처

```
 인물 이름 ──▶ ① director.py ── 스타일·주제에 맞춘 기획안 (제목 N개, 팬 코멘트 30개, 연관곡, 검색어)
                │                Claude(중계 API) + JSON 스키마 검증, 자막마다 안정적인 ID
                │                (선택) 별도 요청으로 '일본어 검수' — AI 검수이며 사람 검수가 아님
                ▼
              ② sources.py ── YouTube 검색 regionCode=JP, videoLicense=creativeCommon → videos.list로 재검증
                │               → yt-dlp 다운로드 (CC만, 받은 파일은 ffprobe로 검사) 또는 내 영상 폴더
                ▼
              ③ scenes.py ── PySceneDetect 장면 분할 (원래 경계 보존) → 긴 연속 장면은 후보 구간 여러 개
                │              → YuNet 얼굴 검출 → 원본 글자 띠·정지 화면 감지 → SFace '가장 많이 나온 얼굴' 필터
                │                (자동 제외될 장면은 주인공 투표에서 뺌, 휴리스틱) → dHash·썸네일
                ▼
              ④ plan.py ── 편집 계획 edit_plan.json  (영상 컷 타임라인 + 자막 타임라인, 서로 독립)
                │            스타일 템플릿으로 자동 배치 → 사람이 컷 표/자막 표에서 수정 (자동으로 덮어쓰지 않음)
                ▼
              ⑤ composer.py ── 컷마다 프레임 단위로 정확히 잘라 이어 붙임 + 제목/자막 PNG 합성 → 1080x1920 30fps
                │                오디오: 무음 AAC (또는 지정한 BGM만, 짧으면 나머지 무음)
                ▼
              ⑥ pipeline.py ── output/<인물>/jobs/<job_id>/ 에 영상·기획안·계획·출처·메타데이터·설정 사본·job.json
                                publish.py: 설명란 CC 출처 표기, (옵션) 비공개 업로드
```

| 단계 | 기술 스택 |
|---|---|
| 기획·검수 | `anthropic` (Claude Opus 5.5, 중계 API + JSON 스키마 검증) |
| 검색/업로드 | `google-api-python-client`, `google-auth-oauthlib` (YouTube Data API v3) |
| 다운로드 | `yt-dlp` (CC 라이선스 확인된 영상만) |
| 장면 분할 | `scenedetect` (ContentDetector) |
| 얼굴 검출/크롭 | `opencv-python-headless` (YuNet / SFace ONNX, 첫 실행 시 자동 다운로드) |
| 텍스트 | `Pillow` + `budoux` (픽셀 폭 기준 일본어 줄바꿈, 금칙 처리) |
| 합성 | `ffmpeg` |

## 3. 설치 / 실행

```bash
pip install -r requirements.txt -c constraints-tested.txt   # 검증한 버전 조합 (ffmpeg는 별도 설치 후 PATH 등록)
```

API 키는 config.yaml과 같은 폴더의 `.env`에 넣습니다 (`중계_API_사용법.md` 참고).

```ini
ANTHROPIC_AUTH_TOKEN=중계서버에서_발급받은_키
ANTHROPIC_BASE_URL=https://codex.hungnguyen.codes
ANTHROPIC_MODEL=claude-opus-5-5
YOUTUBE_API_KEY=AIza...        # CC 소스 검색
```

`.env` 값은 같은 이름의 시스템 환경변수보다 우선합니다. `.env`는 Git에 올리지 마세요. 업로드 시 `secrets/client_secret.json` 필요.

사이드바의 **설정 다시 불러오기**를 눌러야 config.yaml 변경이 적용됩니다 (적용된 설정 버전 표시). `.env`도 다시 읽지만, `.env`에서 **삭제한** 키는 실행 중인 프로세스에서 지워지지 않으므로 앱을 다시 실행하세요. 렌더는 시작 시점 설정의 복사본으로 실행되고, 설정·스타일·소스가 계획 이후 바뀌면 렌더 전에 '오래된 계획'으로 거부됩니다 (소스가 그대로면 편집을 유지한 채 다시 검증 가능).

## 4. 편집 스타일 프리셋 (`shorts/styles.py`, config `styles:`로 덮어쓰기 가능)

| | 청춘·설렘 `youth_romance` (신규 기본) | 칭찬 나열형 `praise_list` (기존) |
|---|---|---|
| 의도 | 웃기 직전 눈빛 → 미소가 번지는 순간 → 여운을 같은 장면 안에서 이어서 | 1.5~2초마다 칭찬 한 줄 |
| 컷 길이 (출발값) | 일반 2.5초 · 핵심 표정 3.5초 · 최소 1.5초 (소스가 짧으면 늘리지 않음) | 자막 읽기 시간 |
| 자막 | 팬 코멘트 약 4~6개(강제 아님)를 **여러 컷에 걸쳐 유지**. 무자막 구간은 선택 | 자막 1개 = 컷 1개 |
| 제목 | 작고 담백: 이름(흰색) + 감정 포인트 1개(연분홍 강조색) | 노란 대형 |
| 구성 템플릿 | 0–3초 핵심 표정 / 3–10초 자연스러운 행동 / 10–22초 한 주제의 다른 순간 / 22–28초 핵심 표정 / 끝맺음 | 없음 |
| 효과음·번쩍임·색 필터·전 컷 줌 | 없음 | 없음 |

이 값들은 **테스트할 편집 가설**이며 일본 시장에서 검증된 정답이 아닙니다. 레퍼런스 영상을 실제로 분석한 결과가 아닙니다. 선호하는 일본 팬튜브 영상을 주시면 컷 길이·자막 밀도·어휘·전환을 관찰해 프리셋을 조정할 수 있습니다. (참고: YouTube 공식 Shorts 편집 안내 https://support.google.com/youtube/answer/13380879 는 텍스트 역할·타이밍을 설명할 뿐 특정 국가 취향이나 최적 컷 길이를 보장하지 않습니다.)

비교: 같은 소재로 두 스타일 계획을 만들어 각각 렌더해 비교할 수 있습니다 (③ 탭 '미리 배치' → 적용/되돌리기). 실제 업로드 후 성과 비교는 인물·곡·길이·게시 시점이 다르면 엄밀한 A/B 실험이 아니므로, 조회수만으로 특정 스타일의 효과를 단정하지 마세요. 작업 폴더의 `job.json`에 스타일·길이·음악 기준 등이 기록됩니다.

### 편집 계획 (`edit_plan.json`, 버전 2)
- **영상 컷**: 장면 ID, 원래 장면 경계, 실제 재생 시작, 프레임 수, 크롭, 역할(일반/핵심 표정), 사람이 지정한 표정 마커
- **자막**: ID, 문구, 종류(팬 코멘트/원본 대사), 표시 컷 범위, 한국어 뜻과 그 기준 문구, 사용자가 적은 장면 설명, 발화 근거, AI 검수 결과
- **음악 기준**: 곡·아티스트·버전/파일·오프셋·마커·타이밍 확인 상태 (파일·직접 확인한 마커가 없으면 **"음악 타이밍 미확인"**. 곡 제목만으로 후렴 시작을 추측하지 않음)
- 설정·스타일·소스 지문, 소스 파일 상태, 제외한 소스, 레이아웃, 제목
- 버전 1(자막 1개 = 컷 1개 `Slot`) 계획은 불러올 때 변환되며 스타일은 칭찬 나열형으로 유지됩니다.

경계 보장: 모든 컷은 `장면 시작 ≤ 재생 시작`, `재생 시작 + 길이 ≤ 장면 끝` (허용 오차 1ms, 시작은 원본 프레임 격자에 맞춤). 출력 프레임은 `fps=30:round=down`으로 만들어 구간 밖 원본 프레임이 나오지 않으며, 세그먼트마다 프레임 수를 확인합니다. 같은 소스의 겹치는 구간은 다시 쓰지 않고, 대표 프레임 지각 해시가 비슷한 장면은 뒤로 미룹니다(부족할 때만 허용하고 표시). 같은 인물이라는 이유로는 중복 처리하지 않습니다.

### 일본어 검수 (선택, 별도 API 요청)
- ③ 탭 **AI 일본어 검수**: 지금 계획에 쓰는 제목과 자막만 묶어 보냄 (원문, 앞뒤 자막, 제목, 스타일, 사용자가 적은 장면 설명)
- 결과: ID별 원문 / 권장 문구 / 한국어 뜻 / 주의할 뉘앙스 / 수정 이유 / 문제 태그(번역투, 부자연스러운 어휘 결합, 의미 변화, 과한 칭찬, 빈정거림 가능성, 원본 대사로 오인, 문맥 부족, 반복, 오탈자) / 장면 적합성
- 장면 설명이 없으면 장면 적합성은 항상 **미확인**. 응답은 ID 누락·중복·추가, 원문 불일치, 빈 문자열, changed와 문구 모순까지 검사하고 실패하면 '검수 실패 — 검수 전 문구'로 표시
- 권장 문구는 자동 적용하지 않음 (선택한 ID만 적용, 원문은 검수 기록에 보존). 문구·문맥·스타일·검수 지시 버전이 같으면 `review_cache.json` 재사용
- **같은 계열 AI의 검수는 사람(일본어 모어 화자) 검수와 같지 않으며 오류 가능성이 남습니다.** 채널 톤의 초기 기준을 정할 때 모어 화자 샘플 검토를 권장합니다.

## 5. 운영 시 주의점

### 비용
- **Claude**: 기획안 1건 ≈ 입력 1~2K, 출력 3~6K 토큰. 검수는 선택한 문구만 보내고 캐시를 씁니다. 중계 서버의 실제 요금은 운영자 정책을 따릅니다.
- **YouTube Data API**: 기본 일일 10,000 units. `search.list` = 100, `videos.list` = 1, `videos.insert` = 1,600.

### 트렌드 지표 (`main.py trends`)
- `avg_views_per_hour_since_upload` = 총조회수 / max(업로드 후 경과 시간, 0.5시간). **최근 1시간·24시간 동안 늘어난 조회수가 아닙니다.**
- 검색 기간(기본 24시간) 안에 **업로드된** 영상만 대상이라 오래된 영상의 재유행은 잡지 못합니다. 길이 필터만 통과한 영상은 '짧은 영상 후보'이며 Shorts 확정이 아닙니다.
- ① 탭 추천은 이 지표를 쓰지 않습니다 (AI 지식 기반).

### 저작권 / 플랫폼 정책 (중요)
- **CC BY도 출처 표기 의무가 있습니다.** `publish.py`가 설명란에 자동으로 넣습니다. 지우지 마세요.
- **CC 필터는 '업로더가 CC로 표시했다'는 뜻일 뿐**입니다. 방송·광고 영상을 제3자가 CC로 잘못 올린 경우가 흔하므로, 공식/본인 채널 업로드인지 사람이 확인하세요.
- **임의 링크 다운로드(틱톡/인스타/일반 유튜브)는 구현하지 않았습니다.** YouTube 약관도 원칙적으로 다운로드를 제한하므로 CC 영상이라도 yt-dlp 사용은 약관 리스크가 남습니다.
- **음악**: 기본 MP4는 무음입니다. 업로드 시 YouTube 앱 '사운드 추가'를 쓰는 것이 가장 안전합니다. 음원을 따로 내려받아 넣는 것은 허락받은 사용이 아닙니다.
- **초상권/퍼블리시티권**: 칭찬 목적이라도 인물을 상업적으로 이용하는 것이므로 요청 시 즉시 삭제할 수 있게 대비하세요.
- **YPP '재사용 콘텐츠' 정책**: 본인 기여(기획·편집·코멘트)가 분명해야 합니다.
- **원본에 박힌 자막·글자는 영상 픽셀의 일부라 지워지지 않습니다.** 추가 자막을 영상 아래로 옮겨 겹치지 않게 할 뿐이니, 글자가 많은 소스는 ③ 탭에서 제외하세요.
- **'가장 많이 나온 얼굴 = 검색한 인물'은 휴리스틱**입니다. 닮은 사람·다른 출연자가 더 많이 나오면 틀립니다. 미리보기로 확인하세요.
- LLM이 만든 대표작/연관곡은 틀릴 수 있습니다(`confidence: low`). 업로드 전에 확인하세요.

### 작업 폴더
- `output/<인물>/jobs/<job_id>/`: `<인물>_<job_id>.mp4`, `script.json`, `edit_plan.json`, `sources.json`, `metadata.json`, `description.txt`, `config_snapshot.json`(비밀 값 없음), `job.json`(상태 running/failed/done, 오류, 실행 환경)
- `output/<인물>/script.json`, `edit_plan.json`: 최신 기획안·계획 (불러오기용). 예전 폴더의 기획안도 그대로 불러올 수 있습니다.
- `work/<인물>/runs/<run_id>/`: 실행별 썸네일·세그먼트·analysis.json(실제 사용한 검출 모드 기록). 실행끼리 섞이지 않습니다.
- `sources.json`은 내 영상 폴더 입력(`--sources-dir`)에 그대로 다시 쓸 수 있는 형식입니다 (`file`/`path` 모두 인식).

| 제안 | 효과 | 비용·위험 |
|---|---|---|
